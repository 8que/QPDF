第一章 项目概述

1.1 项目背景

本项目旨在开发一款轻量级 PDF 图纸标注工具，主要解决大型 PDF 文件在日常图纸标注过程中遇到的效率、性能和操作问题。

目前使用 WPS PDF 处理大型工程图纸时，存在明显的性能问题：

自动保存耗时较长。

编辑过程中页面加载可能卡顿。

部分情况下出现长时间无响应。

严重时可能导致整个 Windows 桌面暂时失去响应。

因此，本项目不以开发一款功能全面的 PDF 编辑器为目标，而是针对高频图纸标注需求，设计一款功能集中、响应迅速、资源占用合理的专用工具。

1.2 核心目标

软件需要实现：

打开、浏览大型 PDF 文件。

在 PDF 任意位置添加文字。

鼠标点击实现连续递增数字标注。

支持数字覆盖和编号插队。

支持框选删除软件自身创建的标注。

支持撤销、重做和异常恢复。

支持标准 PDF 注释导出。

支持其他主流 PDF 软件打开和编辑标注。

支持数千页大型 PDF 的加载与处理。

最终以绿色免安装 EXE 形式运行。

1.3 项目设计原则

轻量化：控制 CPU、内存和磁盘资源占用。

高效率：高频操作优先采用快捷键。

安全性：不修改原始 PDF 页面内容。

兼容性：使用标准 PDF 注释格式。

离线化：不依赖网络、账号和云服务。

可恢复：重要操作具备撤销和恢复能力。

可扩展：采用模块化架构，便于后续增加功能。

3.4 页面渲染

采用按需渲染机制。

禁止一次性将所有页面转换成高清图片。

建议实现：

当前页面优先渲染。

前后少量页面预加载。

页面缓存。

缓存容量限制。

页面离开视野后释放不必要资源。

根据缩放比例动态调整渲染分辨率。

页面渲染采用后台线程。

UI 线程不得执行长时间阻塞操作。

3.4.1 矢量页面渲染

主要面向 CAD 导出的工程 PDF。

要求：

保留矢量内容。

根据缩放比例动态渲染。

避免一次性生成超高分辨率整页图片。

尽可能支持局部区域重新渲染。

保证标注位置与实际 PDF 页面坐标一致。

3.4.2 两种浏览状态

建议提供：

普通浏览模式：

优先保证页面切换速度。

适当降低预览渲染分辨率。

用于寻找目标位置。

精细浏览模式：

根据当前缩放比例提高渲染精度。

用于精确定位标注。

尽量避免不必要的整页重新渲染。

第五章 连续数字标注系统

本模块是 QPDF 最重要的核心功能。

5.1 基本数字标注

数字以纯文本形式显示。

例如：

1、2、3、4、5、6……

不使用：

圆形背景。

方形背景。

气泡背景。

其他装饰图形。

默认数字定位方式为鼠标点击位置居中。

5.2 基本操作

操作流程：

按下数字标注快捷键。

软件进入连续数字标注模式。

默认从数字 1 开始。

每次鼠标左键点击，生成一个数字。

每次成功生成后，编号自动递增。

按 Esc 退出当前模式。

示例：

第一次点击：1

第二次点击：2

第三次点击：3

第四次点击：4

不需要手动输入数字。

5.3 数字样式

支持：

字体。

字号。

颜色。

粗体。

字符间距（可选）。

数字样式可以预先设置。

连续标注过程中不应反复弹出属性窗口。

5.4 起始编号设置

支持：

从 1 开始。

自定义起始数字。

自定义递增步长。

重新开始编号。

例如：

1、2、3、4……

或者：

100、101、102、103……

5.5 编号范围

计划支持三种编号范围：

A. 整份 PDF 统一编号。

B. 每页独立编号。

C. 指定页面范围统一编号。

默认具体采用哪一种，由用户在开发阶段确认。

第六章 数字高级操作

6.1 覆盖标注模式

用途：

修正已有数字标注，或者在原数字位置重新放置数字。

基本要求：

进入覆盖模式。

用户点击目标位置。

软件检测附近本工具创建的数字标注。

删除符合条件的原有数字。

在目标位置放置新数字。

记录完整操作历史。

6.1.1 检测规则

只允许识别本工具创建的数字标注。

禁止误删：

PDF 原始文字。

PDF 原始数字。

其他 PDF 软件创建的注释。

本工具创建的普通文字标注。

6.1.2 碰撞检测

支持设置检测半径。

建议提供：

小范围。

中范围。

大范围。

自定义范围。

如果检测范围内存在多个候选数字，应要求用户确认目标。

6.1.3 编号逻辑

覆盖模式的具体行为需要在开发阶段确认：

是用当前计数器数字替换旧数字。

还是保留原数字的编号，仅修正其位置。

无论采用哪种方式，都必须支持撤销。

6.2 插队标注模式

用途：

在已经完成连续编号的图纸中，补充遗漏位置。

例如：

原始编号：

1、2、3、4、5

发现原本应该存在一个遗漏位置。

插入后：

1、2、3、4、5、6

原来的后续数字自动递增。

6.2.1 功能要求

指定插入位置。

指定插入编号。

自动更新后续编号。

保持原有标注位置不变。

支持操作预览。

支持完整撤销。

6.2.2 编号影响范围

必须明确指定：

当前页面。

指定页面范围。

整份 PDF。

默认不允许未经确认修改整份 PDF 的编号。

6.2.3 事务安全

一次插队操作应视为一个完整事务。

如果执行过程中出现异常：

不允许出现部分数字已经更新、部分数字尚未更新的状态。

必须能够回滚到操作前。

必须记录修改前后的编号映射。

如果无法可靠判断编号关系，应优先采用用户确认，而不是自动猜测。

第十一章 保存与 PDF 导出

11.1 基本原则

原始 PDF 永远保留。

软件不得默认直接覆盖原始 PDF。

第一次导出时默认另存为新文件。

11.2 标准注释模式

将标注保存为标准 PDF 注释。

建议：

文字：FreeText Annotation。

数字：标准文本注释形式。

保留标注独立性。

尽可能保证其他软件可以选中和修改。

11.3 扁平化模式

提供可选扁平化导出。

特点：

将标注合并到 PDF 页面显示内容。

保证其他 PDF 阅读器能够正常显示。

通常不再支持独立编辑。

默认不使用扁平化模式。

11.4 大型文件保存策略

针对 1.3GB PDF：

禁止每次标注操作都重新保存完整 PDF。

导出阶段采用后台处理。

需要研究和测试：

PDF 增量保存。

PDF 全量重写。

注释合并策略。

保存过程内存控制。

磁盘空间预检查。

临时文件管理。

增量保存可以作为优先尝试的方案，但必须验证原文件结构、PDF 加密状态、签名状态及注释兼容性。

不能将增量保存视为所有 PDF 都适用的保证方案。

11.5 安全导出

建议流程：

检查目标磁盘剩余空间。

创建临时输出文件。

后台执行 PDF 注释写入。

完成后重新打开测试文件。

检查页数和注释。

验证通过后移动到正式输出位置。

保留原始 PDF 和项目文件。

如果导出失败，不得破坏原始 PDF。

第十五章 性能优化

本项目必须把性能优化作为核心开发任务。

15.1 内存控制

目标设备只有 8GB 内存。

建议：

限制页面缓存。

限制后台渲染任务数量。

及时释放页面图片。

避免重复创建大型对象。

避免整份 PDF 转换成图片。

避免将所有标注对象长期重复加载到多个模块。

控制 SQLite 查询和缓存规模。

15.2 CPU 优化

N5095A 为 4 核 4 线程低功耗处理器。

建议：

渲染任务限制并发。

避免无意义的后台轮询。

避免频繁重复渲染。

第二十二章 项目最终愿景

QPDF 不追求成为功能庞大的 PDF 编辑器。

它的使命很简单：

让用户能够在大型 PDF 工程图纸上，快速、准确、安全地完成数字标注和文字标注。

理想操作流程：

双击启动 QPDF。

打开大型 PDF。

快速定位页面。

按 F2。

鼠标连续点击，自动生成 1、2、3、4、5……

发现遗漏，进入插队模式。

发现错误，进入覆盖模式。

框选不需要的标注并删除。

Ctrl+S 保存项目。

导出标准 PDF。

使用其他 PDF 软件继续查看和编辑。

最终目标：在 Intel N5095A + 8GB 内存的普通办公电脑上，实现稳定、流畅、可靠的大型 PDF 图纸标注。
